# Языки — шаг за шагом — свой сайт с облаком

Сайт полностью статический: в папке лежат `index.html` и несколько файлов. Аккаунты и облачное сохранение работают через бесплатный **Supabase**. Это готовая база данных с входом по почте.

```
index.html   — сам сайт
supabase.js  — библиотека Supabase (v2, уже внутри — CDN не нужен)
config.js    — сюда вставляются адрес и ключ твоего проекта
schema.sql   — таблица для прогресса + правила доступа
```

Если `config.js` не заполнен, сайт всё равно работает, но хранит прогресс только в браузере.

---

## Шаг 1. Создай проект Supabase (≈5 минут)

1. Зайди на **supabase.com** → *Start your project* → войди через GitHub или почту.
2. *New project*:
   - имя любое, например `edito`;
   - пароль базы придумай и сохрани (на сайте он не нужен);
   - регион — ближайший, например *Central EU (Frankfurt)*.
3. Подожди 1–2 минуты, пока проект создаётся.

## Шаг 2. Создай таблицу

1. Слева **SQL Editor** → *New query*.
2. Открой `schema.sql`, скопируй всё и вставь.
3. Нажми **Run**. Должно появиться *Success. No rows returned*.

## Шаг 3. Настрой вход

**Authentication → Sign In / Providers → Email**:
- *Enable Email provider* — включено (стоит по умолчанию).
- **Confirm email** — лучше **выключить**. Тогда регистрация срабатывает сразу, без письма. Встроенная почта Supabase отправляет очень мало писем в час. Если оставить подтверждение включённым, письма могут не дойти.

Вход по ссылке и «Забыл пароль» всё равно работают через письма. Для личного сайта этого лимита хватает.

## Шаг 4. Вставь ключи в `config.js`

1. **Project Settings → API Keys**:
   - скопируй **Publishable key** (`sb_publishable_…`);
   - если его там нет, возьми **anon public** key (`eyJ…`) на вкладке *Legacy API keys*.
2. **Project Settings → Data API**: скопируй **Project URL** (`https://xxxx.supabase.co`).
3. Открой `config.js` в любом текстовом редакторе и впиши оба значения в кавычки:

```js
window.SUPA_CONFIG = {
  url: "https://xxxx.supabase.co",
  anonKey: "sb_publishable_xxxxxxxx"
};
```

Этот ключ публичный — его можно выкладывать. Данные защищены правилами из `schema.sql`: каждый пользователь видит только свои строки.

⚠️ **Никогда** не вставляй сюда *secret* / *service_role* key.

## Шаг 5. Выложи сайт (выбери один вариант)

### Вариант А — Netlify Drop (проще всего, без git)

1. Открой **app.netlify.com/drop** и войди.
2. Перетащи туда **всю папку** с сайтом.
3. Через несколько секунд появится адрес вида `https://что-то.netlify.app`.
4. Имя можно поменять: *Site configuration → Change site name*.
5. Чтобы обновить сайт: *Deploys* → перетащи папку ещё раз.

### Вариант Б — GitHub Pages

1. На github.com создай публичный репозиторий, например `edito`.
2. *Add file → Upload files* → перетащи все файлы из папки (включая `.nojekyll`) → *Commit*.
3. *Settings → Pages → Build and deployment*:
   - Source: *Deploy from a branch*;
   - Branch: `main` / `(root)` → *Save*.
4. Через минуту сайт будет на `https://<логин>.github.io/edito/`.

### Вариант В — Cloudflare Pages

*Workers & Pages → Create → Pages → Upload assets* → перетащи папку.

## Шаг 6. Скажи Supabase адрес сайта

Это нужно, чтобы ссылки из писем открывали твой сайт, а не `localhost`.

**Authentication → URL Configuration**:
- **Site URL** — адрес сайта, например `https://edito-vlad.netlify.app`.
- **Redirect URLs** → *Add URL* — тот же адрес со звёздочкой: `https://edito-vlad.netlify.app/**`.

Для GitHub Pages — `https://<логин>.github.io/edito/` и `https://<логин>.github.io/edito/**`.

## Шаг 7. Проверь

1. Открой сайт → **Личный кабинет** → *Регистрация* → почта + пароль.
2. Реши пару заданий. Под аккаунтом должно быть написано «Сохранено в облаке».
3. Открой сайт на телефоне, войди тем же аккаунтом — прогресс на месте.
4. В Supabase: **Table Editor → user_docs** — там видны строки `progress`, `quiz`, `ans-…`.

## Полезно знать

- **Бесплатный проект засыпает**, если 7 дней к базе почти не обращаются. За неделю до этого Supabase присылает письмо. Разбудить: открой проект → *Resume project*. Данные сохраняются.
- **Если ты в России.** Supabase и хостинги иногда бывают недоступны без VPN. Проверь сайт с телефона на мобильном интернете без VPN.
  - Если вход не работает, кабинет напишет «Нет связи с сервером», но сайт продолжит работать и сохранять прогресс в браузере.
  - Прогресс уйдёт в облако, когда связь появится: нажми «Синхронизировать сейчас».
- **Несколько аккаунтов на одном устройстве.**
  - При выходе локальная копия очищается.
  - Прогресс, сделанный без входа, переносится в тот аккаунт, в который войдёшь первым.
- **Шрифты** грузятся с Google Fonts. Если они недоступны, сайт покажет системные — всё работает.
- **Ошибка «таблица не создана»** в кабинете значит, что не выполнен шаг 2.
