# Как писать конспект темы (стандарт v2, 30.10.2026)

Конспект — это теория темы (`theory` в данных). Его читают перед заданиями и возвращаются к нему, когда ошиблись.
Цель: за 3–5 минут понять правило и унести 3–4 главные мысли. Всё, что не помогает этому, убираем.

## Почему так (на чём основано)
- **Мультимедийное обучение (Mayer):** слова + картинки запоминаются лучше слов (multimedia); лишнее мешает (coherence);
  главное нужно выделить и показать структуру (signaling); картинка стоит рядом со словом (spatial contiguity);
  материал режется на короткие части (segmenting); разговорный тон помогает (personalization).
- **Когнитивная нагрузка (Sweller):** одна мысль на блок, сначала пример, потом правило, без длинных абзацев.
- **Двойное кодирование (Paivio):** фото к конкретным словам (еда, предметы, места) — второй «ключ» к слову.
- **Замечание формы (Schmidt, input enhancement):** окончания и артикли выделяем цветом и жирным — их нужно заметить.
- **Активное вспоминание (retrieval practice, Rosenshine):** в конспекте есть «Проверь себя» с ответом по нажатию.
- **Лексические блоки (Lewis):** фразы учатся целиком («Je voudrais…», «L’addition, s’il vous plaît»), лучше всего — в диалоге.

## Структура темы (сверху вниз)
1. **Главное** (`KEY([...])`) — 2–4 пункта: правило в одну строку + короткий пример. Это и есть «шпаргалка темы».
2. **Разделы** (`<h3>`) — по одной мысли. Заголовок — вопрос или задача человека: «Как спросить цену?», «Когда du, а когда le?».
   Внутри: пример(ы) → формула/таблица → одна-две строки объяснения.
3. **Коммуникация** — диалог с озвучкой (`CHAT(id, заголовок, реплики)`): реплики с переводом, кнопка «Слушать» (мини-плеер), перевод можно скрыть.
4. **Лексика** — карточки с фото (`PICS([...])`) для конкретных слов; абстрактные слова — таблицей или списком с переводом.
5. **Проверь себя** (`QC([[вопрос, ответ]...])`) — 3 вопроса на главное, ответ открывается по нажатию.
6. **Частые ошибки** (`ERRS([[✗, ✓, почему]...])`) — до 3 строк, только реальные ошибки.
7. **Au fait !** (`NOTE`) — максимум одна культурная заметка.
8. **Фото** (`PHOTOS([...])`) — источники картинок в самом конце (свёрнуто).

## Визуальные правила
- Один цвет — одно значение во всём курсе: м. р. — синий (`g-m`), ж. р. — розовый (`g-f`), мн. ч. — `g-pl`;
  выделенная форма в формуле — `!` в `FX`; правильно — зелёный, ошибка — красный.
- Артикль у существительных всегда показан и окрашен по роду (`GART`, `M`, `Fe`, `P`); у слов на `l’` род подписан.
- Формулы (`FX`, `FXS`) — для схем «что + что»; таблицы (`TBL`, `GRID`, `CJ`) — для парадигм; `FLOW` — для выбора «если… то…»;
  `VS` — для сравнения двух случаев; `SCALE` — для шкал; `SAME` — когда разные формы звучат одинаково.
- Текст: короткие предложения, «ты», без канцелярита; один абзац — до 2–3 строк. Таблица — до 7 строк.
- Картинки: фото 4:3, нейтральные, только для конкретных слов; подпись = слово с артиклем + перевод; нажатие — озвучка.
- Всё французское — в `F()` / `class="fr"`: это даёт озвучку по нажатию и перевод при выделении.

## Язык объяснений
- Двуязычно: `TF(ru, en)`; EN-версия — полноценная, не подстрочник.
- Сравнения с русским/английским — только чёткие параллели (см. CLAUDE.md).
- Не писать «перед контрольной», «будет в тесте».

## Картинки
- Источник: главное фото статьи французской Википедии (Wikimedia Commons, свободные лицензии).
- Скрипт: `python3 tools/wimg.py items.json out` (`{"slug": "wp:Статья" | "File:Имя.jpg"}`; качает по одному запросу с паузой, при 429 ждёт Retry-After; режет 4:3, 400×300 webp) → `python3 tools/wcredits.py out` → `src/static/img/w/<slug>.webp` + подписи в `src/img-credits.js`.
- Плохое фото (ботаническая таблица, картина, схема, коллаж) заменить: указать другой файл или статью и удалить slug из `out/credits.json`.
- Обязательно указывать автора и лицензию (`PHOTOS`).
